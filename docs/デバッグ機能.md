# デバッグ機能 (v0.1.14)

SteamVR Virtual Cockpit を動かしているコンソールの窓で、キーを押すと使えます。
中身はすべて `Joystick.debug_command('名前')` で、キーの割り当ては `_joystick.py` の `DEBUG_KEYMAP` で変えられます。
どのキーもそのセッションの間だけ効き、終了すると元に戻ります。

## キーの一覧

| キー | コマンド | すること |
|---|---|---|
| H | `hud_recenter` | 今の頭の位置を、HUD の奥行き表示の基準にする |
| F | `hud_cycle_mode` | HUD の見せ方を `fakefar` → `far` → `plate` の順に切り替える |
| S | `hud_stats` | HUD の統計を 5 秒ごとに出す / 止める |
| D | `hud_diagnose` | 頭の姿勢の届き方を 3 秒間測る |
| V | `hud_shift_switch_vsync` | ずらしの基準を切り替えるタイミングを、コピー完了から 0〜3 vsync 後で切り替える |
| T | `hud_shift_vsync_target` | ずらしの予測の狙いを「次の画面が光る時刻」と「一定時間先」で切り替える |
| `[` `]` `\` | `hud_predict_down` / `up` / `reset` | 頭の位置の予測に足す時間を -2ms / +2ms / 0 に戻す |
| C | `pivot_calibration` | 左手首のピボット計測 (`throttle_pivot.json` に保存) |
| L | `hud_log_cycle` | HUD のログを 普通 → 大きく → 隠す の順に切り替える |
| P | `dpad_debug` | スティックと十字キー判定の数値の段を出す / 隠す |
| O | `dpad_log` | 十字キーの向きが変わるたびに出る `[DPAD]` の1行ログを出す / 止める |
| K | `hud_late_shift_toggle` | `fakefar` のずらし (`HUD_LATE_SHIFT`) を入 / 切 |
| X | `hud_texture_freeze` | `fakefar` の絵の描き直しを 通常 → 240 → 120 → 80 → 60 → 40 → 20 → 10 → 5 → 1 回/秒 に絞る (ずらしはそのまま) |
| J | `hud_jitter_csv` | 揺れ調査用の CSV の記録を始める / 止める |
| G | `hud_pose_thread` | (検証用) 位置の計算を別スレッドで約 1ms ごとに回す。押すたびに 切 → 姿勢だけ → 全部 (写し方・拡大縮小・ずらしも別スレッド。描く側は代入された値を読むだけ) |
| B | `hud_fixed_ref` | (検証用 v0.1.13) `fakefar` の絵を基準の目 (設計どおりの見え方) の形で描き、頭の動きはすべてずらし (上下左右 + 前後) で直す。絵の中身は更新し続けるが、絵に頭の位置を焼き込まないので、絵が届くたびの跳びが出ない (はず)。ずらし (K) が入のときだけ効く |
| U | `hud_crosshair` | (検証用 v0.1.13) 基準の目の真正面 (HUD の中心) に紫の十字線を出す / 隠す。頭を動かしてもここが景色に対して止まって見えれば、位置合わせが合っている。場所は `HUD_DEBUG_CROSSHAIR_AT` (`eye` / `plate`) |
| Y | `hud_center_toggle` | (v0.1.14) HUD の中心を 低い位置 (既定。フラットのゲームの画面にかぶりにくい) ⇔ 目の真正面 (SACC と同じ。VR 向け) に切り替える。起動時は `HUD_CENTER` |
| `,` `.` | `hud_center_down` / `up` | (v0.1.14) 今の中心の位置のまま、HUD を少し下 / 上へ (`HUD_CENTER_NUDGE_M`、このセッションだけ)。固定する値 (`HUD_CENTER_LOW_ADJUST_M` / `HUD_CENTER_EYE_ADJUST_M`) をコンソールに出す |

キーのないコマンドもあります: `hud_log_toggle` (ログを隠す / 出す)、`hud_log_clear` (ログを消す)、`version` (名前と版を出し直す)。

## 現在時刻の段 (v0.1.7)

通知の段 (CRUISE の下) に PC の時計の時刻を `時:分:秒` で常に出します。
動画・CSV・ログと見比べるときの目印です。
消すときは `HUD_CLOCK_ENABLED = False`、書式は `HUD_CLOCK_FORMAT` で変えられます。

## HUD のログが途中で切れるとき (v0.1.13)

HUD に出すときだけ、括弧 `()` `（）` の中の説明を省いて短くします (`HUD_LOG_SHORTEN`)。コンソールには全文が残ります。
折り返しは 6 行まで (`HUD_LOG_WRAP_MAX`、0.1.12 までは 4)。
v0.1.14 から、ログは HUD の窓で切り抜きません (`HUD_LOG_CLIP = False`。遠くに見せる処理は HUD と同じ)。置き場所は `HUD_LOG_OFFSET_PX` (右, 上) で動かせます。
幅は `HUD_LOG_WIDTH_PX`、行数は `HUD_LOG_LINES`、文字の大きさは `HUD_LOG_FONT_PX` で変えられます。

## スティックのログを消したいとき

P で数値の段を隠し、O で `[DPAD]` の1行ログを止めます。
これで HUD とコンソールにスティックのログは出なくなります。
L でログそのものを隠すこともできます。
`wheel.py` の DEBUG が出す `[MASK]` の行は、`wheel.py` 側の設定なのでこのキーでは止まりません。

## HUD の揺れの調べ方 (X / K / J)

高い負荷のとき、`fakefar` では頭を動かすと HUD が景色に対して揺れます。
原因の候補は「絵 (テクスチャ) と、オーバーレイのずらしが、別々のタイミングで画面に使われること」です。

1. 高い負荷の場所で、頭を左右にゆっくり振って揺れ方を覚える。
2. X を押して描き直しを絞る (押すたびに 240 → 120 → 80 → 60 → 40 → 20 → 10 → 5 → 1 回/秒)。
   通常は「頭が動いていれば約 2ms ごとに描き直す」ので、軽いときは 1 秒に数百回、重いときは GPU 待ちで約 80 回になる。
   - 揺れが消える、または大きく減る: 絵とずらしの切り替えのずれが原因と考えられます。
   - 揺れが変わらない: 原因は別の所にあります (ずらしの予測そのものなど)。
   - 絞っている間は、前後の動きと頭の傾きへの追従が遅れて見えます。これは正常です。見るのは上下左右の小さな跳びだけです。
3. もう一度 X を押して「通常」に戻す。
4. K でずらしを切ると、ずらしなしの揺れ方と比べられます (切ると遅れが大きく見えるのは予想どおりです)。

### CSV (J キー)

J を押すと、`_joystick.py` と同じフォルダに `hud_jitter_日付_時刻.csv` ができ、もう一度 J を押すまで記録します。
終了したときも自動で閉じます。
置き場所は `HUD_JITTER_CSV_DIR` で変えられます。
1行が1つの出来事で、列は次のとおりです。空欄はその出来事に関係のない列です。

| 列 | 意味 |
|---|---|
| `t_ms` | 記録を始めてからの時刻 [ms] |
| `clock` | PC の時計 (時:分:秒.ミリ秒)。HUD の時計 (0.1 秒まで、`HUD_CLOCK_TENTHS`) と動画を合わせるのに使う |
| `event` | `submit` = 絵を SteamVR に渡した / `switch` = ずらしの基準を新しい絵に切り替えた / `shift` = ずらしを更新した |
| `vsync` | SteamVR の vsync の通し番号 |
| `pose_age_ms` | (submit) 頭の位置を読んでから渡し終わるまで |
| `gpu_wait_ms` | (submit) GPU の描き終わりを待った時間 |
| `since_submit_ms` | (switch) 渡してから基準が切り替わるまで |
| `ref_x_mm` `ref_y_mm` | その絵を作ったときの目の位置 (両目の真ん中、seated 座標) |
| `eye_x_mm` `eye_y_mm` | (shift) 予測した目の位置 |
| `dx_mm` `dy_mm` | (shift) ずらした量 |
| `lead_ms` | (shift) 予測の先読み |

ずらしは 1 秒に数百回更新されるので、1 分で数万行になります。
調べたい場面の前後だけ記録してください。
